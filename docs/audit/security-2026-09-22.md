# Security audit, 2026-09-22

A review of prax as it runs for one person. The door and the worker
run on a desktop, or the door on a Pi-class board, reached over a home
LAN or a tailnet. A browser carries the capture extension. Claude Code
carries the MCP plugin. Documents come from the web, from Zotero and
from a drop folder. The question asked of every surface was what an
attacker in that environment can reach. The attackers are someone on
the same network, a web page the person captures, a document a model
reads, and another process on the machine.

The code reviewed is `main` at `888d0f0`. The fixes are the commits
that follow it. Everything below names the module and the line of the
contract, so a later change can be checked against it.

## The trust boundaries

| Boundary | What is on the far side | What holds it |
|---|---|---|
| the network | anyone who can reach the door's port | one bearer token (`prax.auth`), constant-time compared; without one, loopback clients only |
| the browser | pages the person captures; the UI's own origin | the UI's CSP (`api.UI_POLICY`), the session cookie (`HttpOnly`, `SameSite=Strict`), CORS without credentials, the sandbox on served originals |
| a document | text written by someone else, read by parsers, models and the UI | parsers in the worker process; the sanitizer in the UI; the model's tools limited to the door's reads while it surfs (`docs/ask.md`) |
| a model | the ask loop, the extract pass, Claude Code with the MCP tools | the ask loop cannot write; the MCP tools are the door's endpoints; Claude Code asks the person before a tool runs |
| the machine | other processes of the same user | none: the data directory, the command queue and the token file are the user's. A second user on the machine is outside this design |

Severity is for the environment above. *Fixed* names the commit.

| 1 | high | `inbox.fetch_url`, `POST /ingest/url`, the importers, the MCP `capture_url` tool | The door fetched any http(s) URL it was given and kept the response as a document. That reads what the network keeps to itself: llama-server's API on 127.0.0.1, the router's admin page, other hosts on the tailnet, a cloud host's metadata service at 169.254.169.254. ## Checked and found sound

- **SQL.** Every user value reaches SQLite through a placeholder. The
  f-strings in the store interpolate placeholder lists, column names
  from code, and `int(limit)`. The FTS5 match expression is built from
  `\w+` tokens, each quoted (`retrieval._fts_query`); no user string
  reaches `MATCH` raw.
- **Paths.** The archive is addressed by `sha256[:2]/sha256`; a figure
  reference is checked against `[0-9a-f]{16,64}` before it becomes a
  path. The UI is served by Starlette's static files, which refuse a
  path outside the directory. A client's file name is used for
  `Content-Disposition` (quoted) and a temporary file's suffix, never
  for a path.
- **The session.** `POST /session` exchanges the token for an
  `HttpOnly`, `SameSite=Strict` cookie, `Secure` under HTTPS. CORS
  allows extension origins and the configured web origins with the
  `Authorization` header and without credentials. A cookie is never
  sent cross-origin, and a cross-site request cannot carry it.
- **The UI.** `script-src 'self'`, no inline scripts, `frame-ancestors
  'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action
  'self'`, `frame-src` limited to the video embed, `connect-src
  'self'`. Every template interpolation of a data field goes through
  `esc()`; the exceptions are numeric ids and `title` attributes set as
  properties. KaTeX runs with `trust` off.
- **Subprocesses.** Four call sites, every one an argument list, never a
  shell. They are LibreOffice for old office files (headless, its own
  profile directory, a timeout), the supervisor's roles from
  `prax.yaml`, the tray's "open folder", and the autostart entry.
- **Secrets.** The token comes from the environment or `door.token`; the
  Anthropic key from the environment or `up.env`. Neither is written to
  a log, a status file or a response; the refusal line names the client
  and the reason only. `/health` says which mode the door is in, nothing
  else.
- **The ask loop.** Every step is one of the door's reads. The grammar
  limits a local model to ids it has seen. Nothing in the loop writes
  (`docs/ask.md`).
- **Importers.** The Zotero importer opens a copy of `zotero.sqlite`
  read-only. Export files are parsed with `lxml.html`, which does not
  resolve external entities. Office XML goes through `ElementTree`
  (expat with its entity limits) inside the worker.

## What a host should do

1. Set a long token (`secrets.token_urlsafe(32)`), keep `door.token`
   readable by you alone, and bind the door to the private interface.
2. Leave `door.fetch_private` off unless you capture from your own
   network's pages.
3. The worker opens every PDF and office file, so it is the process a
   hostile file reaches first. Keep `pymupdf`, `lxml` and the
   extractors current.
4. Keep backups where the library's own reader is the only reader.
