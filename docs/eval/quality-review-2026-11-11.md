### 1. A project refresh retires the old version as a duplicate: the new text inherits the old extraction stamp and is never extracted, and the old version's facts move onto it, so AU 2's versions cannot be built on this path

*high*, plan; `src/prax/store/documents/library.py:180`; fix: a stage (the short-term part an hour)

**Evidence.** capture/projects.py:540-546 retires the old document of a changed note with retire_document(duplicate_of=new). _join_duplicate then UPDATEs the old document's live edges to source_doc=new and copies 'summary', 'extraction' and 'promote' onto the new document when it lacks them (lines 137-152 and 180-182). select_for_extraction (graph/edges.py:1093-1099) decides what is due from meta.extraction.ontology_version alone, not the text hash. I ran this on a tmp store (scratchpad m2.py): a journal D1 stamped as extracted with one extracted edge, then D2 with a CORRECTION line added, then D1 retired with duplicate_of=D2. D2 was due before the retirement (True) and not due after it (False). D2 carried D1's extraction stamp, and D1's edge, with the quote from D1's text, was now sourced to D2. This range builds further on that path: 023d2ad makes the retirement undoable, and the 11-11 fix _move_nodes_off names 'a re-synced note' as the duplicate case.

**Why it matters here.** AU step 2: each changed text of an entry is a version (example_of, from AS), folded under the newest. Its motivating case is an entry edited after the day, where a CORRECTION is added and the first text relabelled. Today the corrected text is never extracted, so the correction never reaches the graph. Its predecessor's facts are attributed to it. The old version leaves work_versions, which keeps live documents only, so nothing is left to fold. AU's purpose, finding the diagnosis at the moment of need, fails on exactly the entries that were corrected. versions.decide_version is also the only writer of example_of, behind a version_candidates pair and a person's verdict, and the work-naming rule is inline there. A sync cannot state a version without copying that logic.

**Fix.** Short term: on a project refresh, do not copy 'extraction' and 'summary' when the keeper's text_hash differs, or retire without duplicate_of and set meta.retired.of. Either way the new text is extracted, and its facts come from its own text. For AU 2: take the work-naming and example_of statement out of decide_version as a store function (docs, work key, by, run), so the sync can state an entry's versions from its key (file plus heading date) without a candidate pair. Decide whether a superseded version stays live (folded) or is retired, because work_versions shows live documents only.

**The skeptic.** Confirmed in code and by running it. capture/projects.py:540-546 retires the old note of a refreshed project file with retire_document(duplicate_of=new). _join_duplicate (store/documents/library.py:180-182) copies 'summary', 'extraction' and 'promote' to the keeper when the keeper lacks them, and moves the old document's live edges onto it (UPDATE edges SET source_doc). select_for_extraction (store/graph/edges.py:1070-1099) decides what is due from meta.extraction.ontology_version only, with no text_hash test. The safety review of 2026-11-11 did not report it: it only covered the node doc_id side of the refresh. The cost is real today and not only for the plan. ### 8. Graph export (prax-graph/2) does not say which document a node is, so an import gives the node a document by title

*medium*, plan; `src/prax/graph/graphio.py:140`; fix: an afternoon (export field, import claim, a round-trip test)

**Evidence.** `_entity_lines` writes name, type, gid, aliases and labels. It does not write the node's document hash, which is the column migration 69 added (`entities.doc_id`). On import, `import_edge` (store/graph/imports.py:203) calls `link`, and `_link` calls `_claim_node` (edges.py:283-284). That ends in `_node_doc` (store/base.py:837-854), which picks 'of the documents with that title … the live one of the lowest id'. So a friend's `paper` node called `Introduction` (681 shared titles were measured in AS) is claimed for whichever local document has that title, even when settle_foreign landed it as `new`. When the friend's paper is held here, its node cannot land on the local document's node through the hash, although invariant 2 calls the hash the document's global id.

**Why it matters here.** AP is ticked but lists 'sharing over a network' and 'a judge's answer for a likely one' as left to do. Both build on prax-graph/2 records. AP's design says a friend's entity meets this library's 'through resolution …, never by an equal number', and the title lookup at import is the same kind of match. Finding 17 removed the title lookup from the readers; the importer brings it back. Adding the field later means a format version bump and old files that still claim nodes by title.

**Fix.** Write the node's document as `doc_hash` on an entity line of a document type (from `entities.doc_id`).
