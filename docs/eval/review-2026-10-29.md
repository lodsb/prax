# The review of 2026-10-29: global ids, the page lifecycle, the opens

Two reviews of the work since c6891cf: 239a037 (AP built), 653b938 (a
page's lifecycle), bb9926d (the opens), beb5769 (a test's reader). The
safety and correctness review came first, then the quality review with
the project's skill in quick mode. 1,333 lines added in `src` and
`clients`.

## Safety and correctness

Found and fixed, each with a test that fails on the code before:

1. **A label from a hidden document went into an export for a token.**
   `labels_of_entities` read every label of an entity, so `prax export
   --as <token>` carried a name that only a personal document gave. It
   now leaves those out, by the rule a person's page already uses: a
   name only a hidden document gave is as hidden as the document.
   `tests/test_wall.py::test_an_export_for_a_token_holds_only_what_it_sees`.
2. **A failed write of an opening failed the reading.** `GET /get/{id}`
   records an opening (`store.note_open`); a locked database there made
   the read a 500. A failure is now logged and the document served.
   `tests/test_document_opens.py::test_a_record_that_fails_does_not_fail_the_reading`.
3. **An entity line of format 2 without its `gid` was a 500.** The import
   raised `KeyError`, which the door does not turn into a 400. It now
   refuses the file with what is missing.
   `tests/test_graph_import_gids.py::test_an_entity_line_without_its_gid_is_refused`.

Looked at and found sound:

- Every new route (`/graph/imports/likely`, `/decide`, `/undo`) is the
  administrator's: none is in `auth.READER_ROUTES` or
  `CONTRIBUTOR_ROUTES`, and `tests/test_wall.py` walks the lists.
- `--as` sets `store.VIEWER` for the build of the file and resets it in
  `finally`; the hidden set is the store's, cached by viewer.
  `seed_documents` and `subgraph_edges` filter by it, a rule-derived edge
  with a hidden premise included. Pages pass through `get_page`, which is
  guarded. No export holds a `depicts` edge.
- The triggers of migration 64 mint a row's `gid` only when it has none,
  and the refusal fires only on a change of one already set, so the
  minting update passes it. Nothing in the code rewrites `entities` or
  `pages` by delete and insert.
- An answer for a likely row lands on the canonical entity; an undo ends
  only the edges it wrote (`import_held.edge_id`) under a run of its own.
  The import's ending of what a newer file no longer says touches only
  its own producer's edges.
- The lifecycle fix keeps the sources and their order: the links first,
  then the edges' targets, capped at `PAGE_SOURCES`; hidden ones are
  still dropped after.

Left as they are, said here so the next review knows:

- An undo leaves the labels an answer added on our entity. They carry
  the import's producer and run, so `unmerge_run` of that run takes them.
- A likely row from an earlier file of a source stays likely when a
  newer file no longer names it, with no facts waiting on it.
- A file is trusted as the administrator who imports it: a crafted file
  may name one of our pages' `gid`s and add a revision to it, as a file
  of format 1 could by slug.

## Quality

Fixed:

- **Two ways of writing an imported edge.** Format 1 had its own copy of
  the evidence and the review-queue fallback beside `store.import_edge`.
  Both formats now go through one loop and `store.import_edge`; format 1's
  ends are `named` landings, which `store.link` lands by name as before.
  44 lines fewer in `graphio`.
- **`export` at 92 lines.** Its entity and page lines are two functions
  of their own; the file is the same, line for line (the export test's
  stability check).

Looked at and found sound:

- Against the plan: a judge answering a likely row before a person needs
  `foreign_likely` to read and `decide_foreign(by=)` to sign, both there.
  Sharing over a network is the same file over HTTP.
- Independence: no tuned number from the owner's library. `OPEN_EVERY`
  (30 minutes) is a rate, not a measurement.
- Performance on the board: an import makes a few indexed queries an
  entity and an edge, and a commit for each written row, as format 1
  did. The edge read of an export is 15 ms on the live store; the time
  had been the page lifecycle, fixed in 653b938.

Not covered: the UI's new tab beyond the headless click-through of
2026-10-29, and the CLI's `--as` beyond its two lines.
