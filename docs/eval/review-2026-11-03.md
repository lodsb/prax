# The review of 2026-11-03: the media view, the splits, the page moves

Two reviews of the work since e5e183f: cc79395 (a media view), 334ee98
(five complex functions in parts), a0c6ca9 and 4579be8 (pages moved,
renamed and read in windows, migration 67). The safety and correctness
review came first, then the quality review with the project's skill in
quick mode.

## Safety and correctness

Found and fixed, each with a test that fails on the code before:

1. **A move named a parent page its mover may not see.** `move_page`'s
   plan gave the slug of a hidden page above the page, and its note
   wrote it into a revision every reader of the page is shown. The plan
   now names a hidden page `(a page not shown)` (`_slug_shown`), and the
   note never names a personal page, whoever moves it (`_slug_for_all`,
   `personal_sql`).
   `tests/test_page_moves.py::test_a_move_names_no_page_its_mover_may_not_see`.
2. **A move showed and ended a membership in a hidden project.** The
   move read every `part_of` edge of the page. It now reads the viewer's
   (`_seen_project_edges`: a project page and a source document the
   viewer sees), and leaves the others live.
   `tests/test_page_moves.py::test_a_move_leaves_a_membership_its_mover_may_not_see`.
3. **A project's members listed what a hidden document said.** `_members`
   filtered by the member's own document only. A fact a hidden document
   states is now left out, as the walk leaves it out.
   `tests/test_page_moves.py::test_a_projects_members_from_a_hidden_document_are_not_listed`.
4. **A write under an old slug gave a hidden page's new slug.** The
   refusal named the slug the alias led to; it names the one asked.
5. **A rename said which hidden slug exists.** A slug held, now or once,
   by a page the viewer may not see is refused with one message for
   both, saying no more. The refusal itself is an answer, as
   `write_page`'s was before; that is the cost of unique slugs.
   Both in
   `tests/test_page_moves.py::test_an_old_slug_of_a_hidden_page_gives_away_nothing`.
6. **A folder's "(here)" decided its folders too.** The group had the
   folder's own key, which `_in_group` read as the folder and everything
   under it: the row counted one file and its release changed three. It
   is now keyed `=` and the folder (`media.HERE`), which matches the
   folder's own files only.
   `tests/test_media.py::test_a_folders_own_files_decided_without_its_folders`.
7. **A member whose file left every place was in no group.** It counted
   in the totals but no group held it, so no decision reached it. At the
   top it is now the group `(no place)` (`media.NOWHERE`). A group says
   `leaf` when nothing is under it, which the page reads instead of
   guessing from the key.
   `tests/test_media.py::test_a_member_with_no_place_left_is_a_group_of_its_own`.

Looked at and found sound:

- `/media`, `/media/pictures`, `/media/decide` and `/media/undo` are the
  administrator's; move and rename are in `CONTRIBUTOR_ROUTES` only.
- The three new MCP tools make one call to the door each.
- Migration 67 is new; its triggers fit `rename_page`'s order, a rename

- A move ends edges (`valid_to`) and deletes none.
- `decide_media` changes only what is suspected and decided by no

- The five splits of 334ee98 do what the functions did, in the same
  order, with the same messages.

## Quality

Open, for the user's word (`docs/PLAN.md`, "The review of 2026-11-03"):

1. **A page title is found by a scan of every document.** `_members`
   and `_annotated` look titles up in `documents`, which no index
   serves: 50 ms each on the live store, so `get_page` of a project page
   takes 105 ms (58 ms without the text). An index on `documents(title)`
   makes it 1 ms. The same lookup is in `graph/context.py`,
   `retrieval/fusion.py` and `documents/meta.py`. Fix: a migration with
   the index, one helper for the two in `pages.py`. An hour.
2. **Every media request reads all 14,334 members.** 0.1 s a click on
   the desktop, `/media` twice (`media_groups` and `media_counts`).
   Fix: the counts from the rows already read, and `_members` memoized
   by `store_state` as `hidden_documents` is. An hour.
3. **`write_page` and `move_page` commit inside themselves**, so the
   page split by the door (PLAN) cannot be built from them atomically.
   Fix: cores that do not commit, the public functions committing, as
   `_new_page` does. An hour or two; no behaviour changes.
4. **`pages.py` is 1,616 lines**, and the split would take it past the
   2,000-line rule. Fix: a package of parts with an `ORDER`, with item
   3, before the split. Half a day.
5. **The sensitivity decision has three writers in three shapes.**
   `decide_media` writes `meta.sensitivity` with `run` and `before`,
   `set_sensitivity` without, and `media._state` spells the states again;
   `docs/meta.md` declares "state, by" only. Fix: `set_sensitivity` takes
   a run and keeps `before`, `decide_media` goes through it,
   `SENSITIVITY` imported, `docs/meta.md` updated. An hour.

Looked at and found sound: `_project_edges` and the members' edge query
are served by their indexes (0.04 ms); `_children` scans the 590 pages
in 4 ms; `document_hidden` sits in short loops only; `decide_media`
(0.45 s over every member) and `undo_media` (0.18 s) are rare. Nothing
in the media grouping is the owner's: root and path, ISO month, mime.

Not covered: the UI's JavaScript beyond reuse, timings on the board
(the figures above are the desktop's).
